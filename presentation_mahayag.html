CONSULTIME

A Cross-Platform Consultation and Appointment Management System for Mahayag National High School

Philipp Edward Sapalicio, Ednell Sapalicio

ITE Department, Philippine College of Technology | May 2026

Problem Statement

Challenges in manual scheduling and communication at Mahayag NHS

The Scheduling friction

Academic scheduling at Mahayag National High School remains largely manual, relying on paper logbooks, physical bulletin boards, and uncoordinated verbal updates.

This leads to inefficient time management, missed consultation slots, and coordination gaps between students and faculty members.

No Real-Time Sync

Static scheduling leads to consultation block conflicts and double-bookings.

Communication Gaps

No immediate notification channels exist for sudden timetable revisions.

Verification Risks

No vetting mechanisms exist, leaving registration tables open to unverified users.

Low Mobile Footprint

Static systems ignore responsive screen configurations, restricting mobile access.

Objectives of the Study

Digital targets designed to optimize academic scheduling and security

Primary Target

Bridge Coordination Gap

Design, develop, and implement ConsulTime: a real-time consultation and appointment system for Mahayag National High School.

Specific Objectives:
  • Secure Login: Secure authentication systems for Student, Faculty, and Admin.
  • Dynamic Slots: Dynamic slot and availability management tools.
  • Responsive Interface: Responsive appointment booking layouts for students.
  • Verification Toggles: Admin panels to verify and approve accounts.
  • Cross-Platform Deployment: Deploy system as PWA and Android package (.APK).

Scope and Limitations

Operational boundaries of the ConsulTime platform

System Scope
  • Academic consultation scheduling operations only.
  • Three roles: Students, Faculty Members, and Administrators.
  • Appointment requests tracking, scheduling updates, vetting approvals.
System Limitations
  • No built-in video conferencing layout.
  • Compilation wraps to Android (.APK) only; no Apple iOS wrapper.
  • Requires internet connection for database-level real-time updates.

Significance of the Study

Value created for Mahayag National High School stakeholders

To Students

Enables quick reservation of slots, visibility of dynamic changes, and transparent tracking of booking responses, minimizing queue times.

To Faculty

Enables dynamic calendar creation, instant updates to availability windows, and easy approval mechanics without paperwork log jams.

To Administrators

Provides diagnostic panels to approve accounts, monitor server database uptime, and maintain reliable audit histories of consultations.

System Architecture

Integration between PWA client, Supabase cloud gateway, and admin panels

1. Client Layer

Progressive Web Application (HTML5, Vanilla CSS3, ES6 JS) with offline local caching assets via `sw.js` and packaged inside a Capacitor Android native wrapper.

2. Database & Auth Layer

Supabase cloud stack PostgreSQL relational tables (profiles, availabilities, bookings) secured directly by Row Level Security (RLS) rules.

3. Admin Layer

Vetting pipeline reviews document submissions and toggles `is_approved` flags, enabling active session permissions on DB tables.

Database Schema Design I

Structural configuration of User Profiles and Faculty Availabilities

User Profiles Schema (profiles)
  • uuid id: Primary Key referenced to cloud auth identity.
  • text role: Role category (student / faculty / admin).
  • text department & id_number: Institutional alignment.
  • boolean is_approved: Gatekeeper approval flag for faculty vetting.
Faculty Availabilities (availabilities)
  • uuid faculty_id: Foreign Key pointing to profiles.id.
  • int4 day_of_week: Maps recurring days (1 to 5 for Mon to Fri).
  • time start_time & end_time: Boundaries for consultation blocks.
  • date specific_date: Overrides recurring templates.

Database Schema Design II

The bookings junction table structure managing transaction loops

Consultation Bookings relation (bookings)
  • Junction Nodes: dual Foreign Keys (`student_id` & `faculty_id`) linking user identities.
  • Temporal Blocks: maps dates (`appointment_date`) and timing windows (`start_time`/`end_time`).
  • State Constraints: status text inputs limited strictly to `pending`, `approved`, or `rejected`.
  • Dynamic Broadcasts: modifications trigger direct websocket updates to client viewports.

APK Mobile Packaging & Direct Download

Capacitor hybrid native wrapper and file server deployment

Why the Mobile App Matters:
  • Capacitor Runtime: Compiles web codebase into lightweight native Android APK wrapper package.
  • Offline Caching: Service workers preserve layout assets to operate without high mobile bandwidth.
  • Bypass App Stores: Direct download button bypasses verification delays for quick campus deployment.
  • Budget Friendly: 3.69MB package size ensures compatibility with low-end devices (e.g. Vivo Y17s).

System Evaluation Methodology

Standardized testing model and participant demographics

ISO/IEC 25010 Model

Usability trials evaluated system quality according to 5 characteristics:

  • Functional Suitability: Correct task completions.
  • Usability: Navigability and interface clarity.
  • Reliability & Security: Access protection via RLS.
  • Performance Efficiency: Server speed and response times.
Testing Focus Group (N = 26)

The focus group composed of 26 respondents from Mahayag NHS:

  • Students: 15 respondents tested booking forms.
  • Faculty Members: 8 respondents tested availabilities creation.
  • School Admins: 3 respondents tested approvals panel.
